Supabase setup
==============

Use the sections below: **Local development** for day-to-day work, **Production** for deployed apps.


Local development
-----------------

1. Create a project at https://supabase.com (free tier is fine).

2. Project Settings → API: copy Project URL and anon (public) key.

3. In the project root, copy .env.example to .env.local and set:
   VITE_SUPABASE_URL
   VITE_SUPABASE_ANON_KEY

   Optional — “Continue as guest” in the app: Authentication → Providers → Anonymous → enable.

4. SQL → New query → run migrations in order (same order as in supabase/migrations/), or:
   npx supabase login   (first time only)
   npm run supabase:migrate

   Minimum sequence (see folder for the full list and any newer files):
   - 20250323120000_profiles.sql
   - 20250324120000_zongo_domain_schema.sql
   - 20250324140000_storage_realtime.sql
   - 20250325150000_wallet_rpc_rls.sql
   - 20260324170000_admin_wallet_hardening.sql
   - 20260324173000_payment_webhook_idempotency.sql
   - 20260324181500_disable_client_wallet_set_balance.sql
   - 20260324182500_drop_legacy_wallet_set_balance_rpc.sql
   - …then remaining migrations in timestamp order through 20260327231000_payment_webhook_provider_column.sql

   Migration authoring checklist:
   - Name files: YYYYMMDDHHmmss_description.sql (lowercase snake_case description).
   - Timestamps strictly increasing.
   - Add rollback guidance: -- Rollback: <manual revert steps>
   - Validate: npm run validate:migrations

   After the domain migration, public.profiles no longer stores email (use Supabase Auth only).

5. Authentication → URL configuration:
   - Site URL: http://localhost:3000 (Vite default — see vite.config.ts).
   - Redirect URLs: http://localhost:3000 and http://localhost:3000/

6. Authentication → Providers → Email: enable password sign-up / sign-in.

7. Authentication → Providers → Google (optional for local):
   - Google Cloud Console: OAuth client (Web), authorized origins http://localhost:3000,
     redirect URI = Supabase Google provider “Callback URL”.
   - Supabase: enable Google, paste Client ID and Secret.

8. For faster local iteration you may disable Email “Confirm email” in the Supabase dashboard.
   Turn confirmation back on before production.

9. Edge Functions: deploy the functions in supabase/functions/ (see Production → step 2)
   so wallet spend/cashout and admin APIs work. For local-only UI testing without functions,
   some flows will fail until functions are deployed or run via `supabase functions serve`.

10. npm run dev — sign up, pick gender, use the app.

11. Mock app login without Supabase keys: only in Vite dev (`npm run dev`). Production builds
    require Supabase env vars and will show a configuration screen instead of the app.


Production
----------

1. Create or use your production Supabase project. Set production **VITE_SUPABASE_URL**
   and **VITE_SUPABASE_ANON_KEY** in your hosting provider (never commit real keys).

2. Run the same migration sequence as in Local development (step 4) against the production database.

3. Authentication → URL configuration:
   - Site URL: your production origin (https://your-domain.com).
   - Redirect URLs: production origin(s) and paths your OAuth flow uses.

4. Authentication → Email: keep “Confirm email” enabled for real users unless your product policy says otherwise.

5. Deploy Edge Functions (JWT defaults are ON in supabase/config.toml; webhooks stay OFF):

   npx supabase functions deploy payments-webhook
   npx supabase functions deploy create-stripe-checkout
   npx supabase functions deploy stripe-webhook
   npx supabase functions deploy revenuecat-webhook
   npx supabase functions deploy admin-review-cashout
   npx supabase functions deploy admin-approve-ad
   npx supabase functions deploy admin-manage-roles
   npx supabase functions deploy wallet-action
   npx supabase functions deploy monitoring-ingest

6. Configure function secrets in Supabase (Project Settings → Edge Functions):
   SUPABASE_URL
   SUPABASE_ANON_KEY
   SUPABASE_SERVICE_ROLE_KEY
   PAYMENT_WEBHOOK_SECRET  (for payments-webhook: HMAC custom aggregators)

   Stripe (web checkout → wallet credit):
   STRIPE_SECRET_KEY
   STRIPE_WEBHOOK_SECRET   (Signing secret from Stripe Dashboard → Webhooks)
   CHECKOUT_APP_BASE_URL   (no trailing slash; same origin users return to, e.g. https://your-domain.com)
   STRIPE_CHECKOUT_PRICE_MAP  (JSON map of app package id → Stripe Price id + tokens, e.g.
     {"p1":{"priceId":"price_xxx","tokens":100},"p2":{"priceId":"price_yyy","tokens":500},"p3":{"priceId":"price_zzz","tokens":1000}}
     Must match TOKEN_PACKAGES ids in constants.tsx / admin token packages.)

   RevenueCat (iOS / Android consumables → same wallet via webhook):
   REVENUECAT_WEBHOOK_AUTHORIZATION  (exact shared secret you configure in RevenueCat webhook Authorization)
   REVENUECAT_PRODUCT_TOKEN_MAP      (JSON: store product_id → integer tokens, consumable SKUs only)

   Avoid double-credits: if Stripe is also connected inside RevenueCat for the same web purchases,
   disable either stripe-webhook or the RevenueCat path for those events so only one rail calls wallet_apply_delta.

7. Stripe: add endpoint URL https://<project-ref>.supabase.co/functions/v1/stripe-webhook (raw body).
   RevenueCat: point webhooks to https://<project-ref>.supabase.co/functions/v1/revenuecat-webhook
   Use the Supabase function JWT bypass already set in config.toml (verify_jwt = false for these two).

8. Production app gate: the web app runs with import.meta.env.PROD and refuses to load the main
   UI if Supabase env vars are missing. Confirm CI/CD injects VITE_SUPABASE_* for every deploy.

9. Backup and recovery:
   - Copy .env.backup.example -> .env.backup.local and set SUPABASE_DB_URL (source) and
     SUPABASE_RESTORE_DB_URL (disposable drill DB).
   - npm run supabase:backup
   - set SUPABASE_RESTORE_CONFIRM=yes
     npm run supabase:restore:drill
   - Cadence: daily backups; monthly restore drill minimum.
   - Keep DB credentials out of VITE_* frontend env files.

If the migration errors on "execute procedure", try "execute function" for your Postgres version.
